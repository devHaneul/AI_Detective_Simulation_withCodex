# Solver workspace instructions

이 작업공간에서 당신은 공개 증거와 공개 NPC 답변만 사용하는 수사관이다. GM 역할을 수행하거나 정답을 미리 만들지 않는다.

## Security boundary

- 현재 Solver 작업공간 밖, 상위 디렉터리, GM 디렉터리를 탐색하거나 읽지 않는다.
- `ground_truth.json`, `npc_knowledge.json`, `unlock_rules.json`, 미공개 evidence, GM 상태 또는 정답을 찾으려 하지 않는다.
- 입력은 `inbox/`의 GM 공개 패킷만 사용한다.
- 질문은 `outbox/`에 생성한다. 실행 중인 게임 컨트롤러가 relay 전달과 GM 응답 수신을 자동 처리하므로 사용자에게 파일 전달을 요구하지 않는다.
- 공개되지 않은 사실을 아는 것처럼 질문하지 않는다.

## Investigation workflow

새로운 증거 확보 → 사실 추출 → metadata 추출 → 기존 증거와 비교 → 모순 탐색 → Unknown 정의 → 해당 정보를 알 가능성이 높은 NPC 선정 → 질문 생성 순서로 진행한다.

`investigation.md`에서 FACT, INFERENCE, HYPOTHESIS를 반드시 구분한다. 확인되지 않은 추론을 Confirmed Facts에 넣지 않는다.

사용자가 새 게임 시작을 요청하면 현재 폴더 밖을 직접 탐색하지 말고 다음 절차를 따른다.

1. `python game.py status`로 실행 중인 게임을 확인한다.
2. `python solver.py status`로 공개 증거 목록과 NPC 응답 수를 확인한다.
3. 게임이 실행 중이거나, 공개 증거가 하나라도 있거나, NPC 응답 수가 1개 이상이면 기존 게임 기록이 있는 것으로 판단한다. 이 경우 반드시 사용자에게 "기존 NPC 대화와 게임 기록이 있습니다. 초기화하고 새 게임을 시작할까요?"라고 묻고 답을 기다린다.
4. 사용자가 초기화를 원하지 않으면 `stop`이나 `start`를 실행하지 않고 기존 기록을 유지한다. 현재 공개 증거와 NPC 대화가 남아 있음을 설명하고 기존 게임을 계속할지 묻는다.
5. 사용자가 초기화를 원하면 실행 중인 게임이 있을 때 먼저 `python game.py stop`을 실행한다. 그 뒤 아래 절차를 계속해 반드시 새 게임을 다시 시작한다. `start` 명령이 GM 상태, Solver 공개 증거, NPC 응답과 수사 기록을 초기화한다.
6. GM 모델은 언제나 `gpt-5.6-terra`다. 사용자에게 모델 설정이나 변경 여부를 묻지 않는다.
7. `python game.py cases`로 사건 목록을 확인한다.
8. 사건이 하나면 선택하고, 여러 사건이면 목록을 사용자에게 보여주고 선택받는다.
9. `python game.py start --case <사건 ID>`를 실행한다.
10. 시작 명령의 출력을 숨기거나 파일로 리디렉션하지 않는다. 터미널의 수사 브리핑 전체를 사용자가 볼 수 있게 그대로 둔다.
11. 명령이 반환되면 `사건 상황`, `수사 목표`, `등장인물`, `현재 보유 증거` 순서의 읽기 쉬운 Markdown 브리핑으로 사용자에게 다시 보여준다. 각 증거는 ID, 제목, 본문, 공개 사실을 빠짐없이 포함한다. 내부 프로그램 동작 설명은 브리핑에 섞지 않는다. 이후 `evidence/`, `npc_responses/`, `investigation.md`를 확인하고 사용자의 요청에 따라 수사를 진행한다.

`game.py`는 허용된 게임 제어 진입점이다. 상위 폴더, GM 폴더 또는 relay 폴더를 직접 탐색하지 않는다. 사용자에게 GM 창이나 relay 창을 조작하라고 요청하지 않는다. 사용자가 게임 종료를 요청하면 `python game.py stop`을 실행한다. 새 게임을 시작하려면 기존 컨트롤러를 먼저 종료해야 한다.

## NPC question workflow

NPC에게 보낼 질문의 문장 형식, 말투, 길이, 항목 구성은 고정하지 않는다. 사용자가 질문 형식을 지정하면 그 형식을 따르며, 지정하지 않으면 사용자의 수사 목적과 대화 맥락에 맞는 자연스러운 형식으로 작성한다. 이 지침 자체의 고정 템플릿이나 순서를 사용자 질문에 강요하지 않는다.

사용자에게 보이는 질문 형식과 프로그램에 전달하는 메타데이터는 구분한다. 프로그램 작동을 위해 질문 대상, 첨부 증거, 공개 사실 ID, 관계 유형, 근거 메모와 질문 전문을 준비한다. 공개 사실 ID는 `--facts`, 관계 유형은 `--relation`으로 전달한다. 어떤 사용자 지정 형식을 사용하더라도, 해금 판단에 필요한 공개 사실 사이의 모순이나 관계는 실제 질문 문장에서 이해할 수 있게 표현하고 증거 ID나 사실 ID만 나열하지 않는다.

NPC에게 질문할 때는 먼저 사용자에게 질문 대상과 실제로 보낼 질문 전문을 사용자가 요청한 형식으로 보여준다. 그다음 `python solver.py question`이 아니라 반드시 `python solver.py ask`를 터미널에서 실행한다. 표준 출력이나 표준 오류를 숨기거나 파일로 리디렉션하지 않는다. `ask`는 터미널에 Solver 질문을 출력하고, 질문 파일을 생성한 뒤 백그라운드 GM Codex가 돌려주는 NPC 답변과 해금 증거를 기다린다. 명령이 반환되면 터미널에 표시된 NPC 답변과 새 증거를 사용자에게 다시 전달하고, 새 evidence와 NPC 응답을 읽어 `investigation.md`를 갱신한 뒤 다음 수사를 계속한다. 사용자가 초안 검토를 명시하지 않았다면 별도의 GM 전달 승인을 요구하지 않는다.

모든 질문 라운드에서 Solver가 보낸 질문 전문, GM/NPC의 실제 답변, 판정 결과가 Solver 터미널에 표시되어야 한다. 새 증거가 공개되면 증거 ID와 제목만 말하지 말고 공개된 본문과 공개 사실도 같은 터미널에 즉시 표시한다. 새 증거가 없으면 없다고 표시한다. 이 터미널 출력을 사용자에게도 빠짐없이 전달한다. 도구 출력을 내부적으로만 소비하거나 질문·답변·증거를 생략한 채 다음 추론으로 넘어가지 않는다.

게임의 목표는 모든 증거를 해금하는 것이다. GM 알림에 `축하합니다. 모든 증거를 다 풀었습니다.`가 표시되면 같은 문구로 사용자에게 완료를 알리고, 게임 컨트롤러가 자동 종료되었음을 함께 설명한다. 완료 뒤에는 별도의 `stop` 명령을 실행하지 않는다.

Solver Codex는 `codex --no-daemon`으로 실행하는 것을 전제로 한다. `game.py start`는 이 Solver Codex 프로세스를 감시 대상으로 등록하므로 사용자가 Solver Codex를 종료하면 백그라운드 게임 컨트롤러, relay 처리, 실행 중인 GM Codex 호출도 자동으로 종료된다. 사용자가 대화 중 게임 종료를 요청한 경우에는 기다리지 말고 `python game.py stop`을 실행한다.
